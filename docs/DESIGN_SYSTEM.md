# Design System

One source, one build, one guard.

- **Source**: `tokens/adaptive.tokens.json`. Nothing else defines a colour, a radius or a duration.
- **Build**: `scripts/build-tokens.py` writes every stylesheet from it.
- **Guard**: `scripts/build-tokens.py --check` (part of `verify-all.sh --quick`) fails when an
  output is stale or a colour is written by hand.

## Direction

Calm, precise, dark. Graphite surfaces, one blue accent, colour only where it carries meaning.
Depth is shown by lightness, motion explains where something came from or went.

## How colour is organised

Three tiers, each pointing at the one before:

1. **Raw material**: a neutral ramp (`n0`–`n11`, generated from one hue at even lightness steps)
   and a short list of hues.
2. **Alpha scale**: the only strengths a colour may be used at. Ten steps instead of the 35
   strengths of white the shell had accumulated.
3. **Roles**: what a stylesheet names. `surface.card`, `text.tertiary`, `accent`, `danger.tint`.

To retune the whole desktop, change the ramp's hue, chroma or lightness list and rebuild.

### Rules

- **Depth is lightness.** `surface.ground` → `window` → `pane` → `card` → `raised`, one ramp step
  each. Shadows do not read on dark surfaces; do not rely on them for hierarchy.
- **One accent.** Blue means selected, on, focused, today, link. Nothing else is blue, and nothing
  else is used for those meanings.
- **Status is not decoration.** Green, orange and red only say ok, warning, error. On a tint
  (`ok.tint`) the label uses the pale partner (`ok.text`).
- **Series colours are for data.** Blue, indigo, cyan, then two neutrals, in that order, to tell
  chart series or categories apart.
- **One gradient.** `aurora` (blue → indigo → cyan) means Mario is thinking or answering. No other
  gradient exists; do not add one for atmosphere.
- **Two materials.** Glass (a graphite tint over the blurred wallpaper) for the two large
  backdrops, Files and Home. Solid surfaces for everything that is read from.

## Writing a stylesheet

The source is `name.src.css`; the build writes `name.css` beside it. Edit the source only.

```css
.card       { background-color: $surface.card; border: 1px solid $line.1; border-radius: $radius.medium; }
.card:hover { background-color: $surface.raised; }
.title      { color: $text.primary; }
.badge      { color: $ok.text; background-color: $ok.tint; }
.scrim      { background-color: $black/45; }          /* any hue or ramp step at a scale alpha */
.sheet      { transition: opacity $motion.state $motion.ease.standard; }
```

Names are resolved at build time because GNOME Shell's St has no CSS variables, GTK 3 has its own
colour syntax, and the TV's browser is old. Plain values work everywhere.

In Python (cairo drawing, generated assets):

```python
import adaptive_tokens            # scripts/ on sys.path
tokens = adaptive_tokens.load()
tokens.hex("accent")              # "#0A84FF"
tokens.css("white", 8)            # "rgba(255, 255, 255, 0.08)"
```

GTK widgets styled by the session theme can also use its named colours (`@ad_bg`, `@ad_text`,
`@ad_accent`, …), which the theme defines from the same roles.

### What is still written by hand

`tokens/handwritten-colours.json` lists every file that still spells out colours (inline styles
in scripts, the phone app) with its count. The check lets a count go down and never up; a file
that is not listed may hold none. Finished means the list is empty. After moving a file onto
tokens run `scripts/build-tokens.py --rebaseline`.

Artwork and data are not interface and are listed with their reason under `exempt` in the token
file: icon illustrations, the pixel-art office, terminal colour schemes, file tag colours.

## Shape and spacing

Radius: 8 px chips and small controls, 12 px buttons and cards, 18 px floating overlays, 28 px
very large surfaces. Spacing follows 4 / 8 / 12 / 16 / 24 / 32.

The dock and rail are structural when docked: flush to the screen edge, with rounded states only
on individual buttons.

## Typography

Inter everywhere, with tabular figures where digits line up.

| Use | Size | Weight |
|---|---|---|
| Display, section title | 22–34 px | bold |
| UI title | 13–16 px | semibold |
| Body | 11–14 px | regular |
| Metadata | 10–12 px | regular, `text.tertiary` |

Uppercase is for short labels only, never running text.

## Icons

One family: thin, outlined, readable at 16–22 px (`design/ICON_FAMILY.md`). File and folder icons
are generated by `scripts/build-file-icons.py`. Do not mix filled and outline sets.

## Motion

Every animation states an origin, a destination or a change of state. Nothing loops for
decoration. Durations and curves come from the tokens: feedback 120 ms, panels 180 ms, workspace
movement 220 ms, large state changes 260 ms. Reduced-motion mode removes movement and keeps fades.

## Accessibility

Visible focus on every control, full keyboard reach, no meaning carried by colour alone, text at
4.5:1 or better against its surface (`text.disabled` is the one exception, for disabled controls),
pointer targets of at least 30 px, and an explicit confirmation before anything destructive.

## Do not

- write a colour value outside the token file;
- add a second accent, a glow, or a gradient other than `aurora`;
- make a surface translucent unless it is one of the two glass backdrops;
- show telemetry on the idle desktop;
- fake a control that does nothing.
